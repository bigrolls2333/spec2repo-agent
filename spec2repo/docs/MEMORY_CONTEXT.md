# 任务记忆与上下文管理

本次改造解决两个问题：长任务裁剪对话后丢失进展和失败原因；进程恢复后，记忆描述的代码与实际恢复的代码不一致。实现采用结构化任务笔记、可分页读取的工具证据，以及与提交快照绑定的恢复规则。

## 每次模型请求包含什么

1. 固定系统规则与 CoreSpec，规定业务和工具权限边界。
2. 从数据库读取的计划、剩余预算、独立验收反馈。
3. 任务记忆：模型主动记录的进展、决策、失败尝试、下一步，以及平台记录的最近 12 条工具观察和最近 4 条失败观察。
4. 最近的完整 assistant/tool 消息组。

模型通过 `update_task_memory` 替换结构化笔记。每类最多 4 条、每条最多 300 字符，引用最多 12 个证据 ID。替换而非追加避免笔记无界增长，调用时应保留仍然重要的旧决策。笔记是模型陈述，不能覆盖 CoreSpec，也不能作为验收通过的依据；平台观察记录工具在当时的执行结果，不代表文件以后没有被修改。

## 工具输出如何按需取回

工作区工具的返回内容进入独立的 `tool_evidence` 表，包含任务、规格指纹、执行代次和结果。提示词通常只放最多 1600 字符的头尾预览，以及证据 ID。失败输出也保存，避免真正的错误信息被长日志挤掉。

模型可调用 `read_tool_output`，按字符偏移分页读取，每页最多 8000 字符。读取结果包含原工具是否成功、退出码和下一页位置；读取操作成功不等于原命令成功。证据取回本身不再次生成证据，避免递归膨胀。

单条输出最多保存 64 KiB UTF-8；每任务最多 256 条、总计 4 MiB 序列化证据。额度统计与写入在任务行锁保护下完成，避免并行工具同时突破上限。达到额度时返回明确的不可保存标记，工具执行结果仍然反馈。证据不会自动清理，后续长期部署需增加归档和保留周期。

这里保存的是**沙箱已捕获的有界输出**。Docker 层只读取最后 100 行并限制长度，因此终端证据标记 `capture_limited=true`，不能当作完整 stdout。保存前移除已配置模型密钥的精确匹配，并遮盖常见 key/password/token 格式；这是有限脱敏，不是完整敏感信息识别系统。

## 裁剪策略和预算

原有裁剪阈值保持：请求 JSON 大于 24,000 字节、历史大于 48,000 字节，或请求预留将超过剩余累计额度时，优先删除最旧的完整工具消息组。最新一组保留，避免破坏 tool_call_id 配对；无法压到 64,000 字节硬上限以下时，明确终止，不悄悄丢弃规格。

每次删除会写 `agent.context_compacted` 事件，记录删除组数及前后字节量。这个压缩是确定性投影加模型维护的结构化笔记，没有额外调用模型生成自由文本摘要。

上下文长度和累计花费预算是两个概念。字节阈值约束单次请求大小；运行累计额度仍在模型请求前预留，裁剪不退回已消耗预算。UTF-8 字节加输出 allowance 是保守估算，不能用作真实计费 token；真实模型 usage 单独记录。

## 故障恢复为什么要绑定快照

`task_memories` 以任务和 generation 为主键。所有读写先验证租约、任务状态、持有者和规格指纹；过期 Worker 的写入会被拒绝。

调用 `finish` 时，记忆绑定的 snapshot_hash 与 Agent 状态切换、提交快照指针在同一个 MySQL 事务中写入。新一代执行只有找到相同任务、相同规格、相同已提交快照的记忆，才会复制它；其余未提交记忆不会载入。

例如：快照 A 包含基础 API，随后修复生成了文件 B，但提交前 Worker 崩溃。恢复仍加载 A，也只加载 A 对应的记忆，不会声称 B 已完成。旧代次证据只有被匹配快照的笔记或观察索引引用，才能在新代次读取；知道证据 UUID 本身不能绕过任务隔离。

这意味着过程笔记虽然落库，恢复粒度仍是已提交快照。若要做到每个工具步骤恢复，必须同时对文件系统建立更细粒度检查点，不能只保存更多聊天记录。

## 与参考产品的关系

Claude Code 将项目规则与自动记忆区分，采用小索引和按需读取主题文件；我们借鉴的是分层和按需加载思路，单任务笔记不是它的跨会话自动记忆实现。参考：[Claude Code memory](https://code.claude.com/docs/en/memory)。

Codex 的 AGENTS.md 是分层项目指令；我们把业务规格与模型经验分开，避免把模型笔记升级为权限规则。参考：[Codex AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。

Codex 指南中的 Responses compaction 与本项目的 Chat Completions 接口不同。本实现使用透明的结构化记录和完整消息组裁剪，没有声称调用 `/compact` 或持有其加密状态。参考：[Codex prompting guide](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide)。

本批聚焦单个长任务；跨任务经验的筛选、过期、冲突处理及项目规则文件加载属于后续范围。自主性体现在模型决定记什么、何时检索证据、如何调整实现，平台负责隔离、容量和事实边界。
